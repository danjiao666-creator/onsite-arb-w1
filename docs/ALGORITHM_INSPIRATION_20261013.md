# r43 算法研究参考：开源方法思想与 OnSite 改进假设

> 2026-10-13｜研究笔记 / Codex 阅读入口｜状态：**仅研究参考，未实施、未验证、未授权运行实验**。
>
> 目的：把已核对的外部开源算法，逐一映射到 r43 真实失败机制；借鉴思想，不照搬架构、不复制未审查代码、不自主启动搜索。本文不改变仓库现有版本身份和实验结论。

## 0. 我们当前的算法认识

**r99**：W1 周车预测 → 路线与主候选 → 理想运动评价 → CloseGuard 两秒复核和可能覆写 → 实车执行。

**r43**：W1/当前观测预测 + 路线 → 主候选 / 恢复候选 / 移位续行共同生成 → 统一 ExecutionEvaluator 按真实控制器及官方运动学推演 → 矩形占用与车身地图门 → 单一仲裁 / ExecutionDecision → 下一帧反馈。

r43 的基本方向值得保留：**“是否可执行、前缀是否安全”在同一评价框架内回答**，不再让不同模块使用彼此冲突的安全口径。但“前2秒检查通过”≠“长期安全”≠“可在期限内完成”。六秒远期交通证据更弱；有限候选无解不能推出物理无解。

数据范围：r43 当前已归档的**原130场 115到达/3碰撞/12超时**，追加开发100场 **84/5/11**，合计230场 **199到达/8碰撞/23超时**；另有部分成功场景的车身地图外伸问题。r43 尚未晋级替换 r99，旧成功存在回归，且尾部时延有风险。数字来自 [版本比较](UPDATE_20261010.md) 与 [31场失败归因](../candidates/r43/analysis/nonarrival_attribution_r59/v2/REPORT.md)，不是官方线上成绩。原130内存归一化7个反序目标的协议影响，应与算法收益分开。

**研究总问题**：在保留统一真实执行评价的前提下，怎样生成**安全、可执行、可持续续行、且可按时真正入框**的行动序列？开源仓库只提供备选思想，不提供 OnSite 正确性保证。

## 2. 对应31场失败，提炼我们自己的算法假设

### A. 目标导向路线：先保证“有通向盒内的路”，再优化驾驶

**已知证据**：追加开发集中 3 场（2422cutin168、1lanechange42、1cutin74）存在目标路线不穿目标框的诊断。这不是靠加大制动/加速即可解决的缺口。

**借鉴**：CommonRoad Route Planner 的目标导向路线生成和终点条件思想。

**适合 r43 的改进假设**：
1. 在候选路线生成/筛选时，使用**官方有序目标谓词**检验中心轨迹能否进入盒，而不是只看目标中心距离或 ETA；反序目标的协议修正必须显式记录，不能暗中改变评测口径。
2. 对没有入框几何见证的路线，尝试合法终端连接/终点附近备选路径；保留车道图拓扑、道路和横向连续性约束。
3. 将“几何进入目标盒”“官方动力学可执行进入目标盒”“预算内进入目标盒”分别记录，不能互相代替。

**反例风险**：为了穿盒而生成不可转弯、越道路边界或耗时更长的路线；因此不能只用几何穿盒宣告成功。

### B. 进度与起步承诺：避免“永远计划下一秒再走”

**已知证据**：5 场高速超时具有“刹停后每帧继续计划未来加速，却实际不启动”的特征：highway_merge_2_1_464、highway_merge_3_1_301、highway_merge_3_1_223、highway_merge_3_1_432、highway_merge_2_1_482；9_381 则表现为长期低速停走。

**借鉴**：Autoware 起步行为阶段、滚动优化执行一致性、CommonRoad Reactive Planner 终端时间约束。

**适合 r43 的改进假设**：
1. 明确区分“等待真实交通间隙”“执行有计划的让行”“已经满足安全条件、需要开始起步”，给出每帧**不前进的具体安全约束证据**。
2. 为已选的阶段性方案记录**剩余动作时间和可检验进度**；移位续行是候选且每帧必须重检，不是无条件强制坚持旧动作。
3. 比较“现在开始加速”和“延后加速”的真实可执行终端状态/入框时间，而不允许尾段乐观 ETA 永远掩盖前段零进度。
4. 保证存在新的周车风险、道路风险或候选不合格时可以立即撤销承诺；避免为起步硬冲交通。

**关键研究问题**：在可观测风险没有新增、候选执行仍安全的情况下，为什么连续数十帧都把加速推到未来？是候选时序参数化、阶段归零、评价排序，还是执行门控？先分账，不要先写状态机补丁。

### C. 分层、自适应候选搜索：从“增加数量”改为“补足缺失行为”

**已知证据**：r43 已有主规划、恢复、制动后起步、移位续行等候选，但有限集合失解和预算失解仍发生；13 场超时是在持续运动中推进不足。不能把所有失解都理解为真实控制空间无解。

**借鉴**：CommonRoad 的 Frenet 五次多项式多终端采样 + TUM 的行为 primitive/图搜索 + PythonRobotics 状态格示例。

**适合 r43 的改进假设**：
1. **先分行为**：保持前进、让行、通过间隙、停车后起步、合法换道，而不全靠同一个固定纵向模板表达。
2. 每类行为只生成有差异的**终端位置/速度/时间/横移时机**；依据当前无解原因做局部增密，不盲目全局网格爆炸。
3. 所有新候选最终仍走 r43 **同一个真实控制器 rollout、官方 checked_action、矩形占用、全车身道路评价与仲裁**；不能给新候选开安全例外。
4. 候选更丰富不意味着被证明安全或优于 r43，必须找到目标场景上的“族外、道路内、可执行、带续行证据”的反例见证。

### D. 未来可恢复性：避免当下2秒安全，却把自己开入死局

**已知证据**：r43 的前缀可行状态不代表下一帧存在可用后缀；原来的 12_36、12_60 一类事故也揭示恢复决策可能在较早时刻消耗逃逸余量。

**借鉴**：CommonRoad-Reach 的可达集/安全走廊和 MPC 终端约束的思想。

**适合 r43 的改进假设**：
1. 在执行候选末端，估算可恢复状态集合、终端安全区域或至少一个经检验的安全续行后缀。
2. 如果一个前缀能避免近端碰撞，却使后续所有已知候选失解，应当记录并与其他前缀比较；必要时更早调整停车位置或通过时机。
3. 动态障碍预测本身有限、地图可能缺失、集合可能近似，因此要将“有有限安全见证”“近似可达”“正式安全保证”严格区分。
4. 初版只对既有失败窗口做**离线可达性对照**，验证是否提供原候选没有的有效信息；不要先接入复杂在线求解器。

### E. 周车预测和风险分支：精准地修漏险/误拒，不全盘替换 W1

**已知证据**：r43 的一些碰撞涉及已观测对象预测漏险、加速度支持分支的误拒与逃离候选限制；终帧首次出生的两次事故则不可能靠没有输入历史的 W1 外推出具体车辆。

**借鉴**：多模型预测、运动假设证据校准与鲁棒占用；外部轨迹规划工具主要提供评价思想，不证明其预测器更好。

**适合 r43 的改进假设**：
1. 逐固定观测检查 W1/CV/支持加速等预测分支实际提供的覆盖与误拒，分对象、时刻、车辆位置和姿态。
2. 用**当下可得历史**判断运动假设的适用条件，研究分支保守性随成熟度变化；不能用未来真实轨迹作为在线输入。
3. 不因为某条分支在一场景误拒就直接删掉；已有实验发现简单删支可能让其他碰撞更早发生。
4. 已知车辆安全预测、候选可执行性、终帧出生可见性应分开归因，不混成“W1 不准”。

## 3. 统一验证口径：避免“把局部进步做成整体退化”

以下是**未来实验应遵守的判定原则**，不是本文件授权启动实验：

- **基线**：冻结 r43，明确原130和追加100两组场景及不同目标修正协议；与 r99 对照时保留原始结果。HOLD 仍保持封存。
- **一次仅一个研究假设**：先给出具体失败窗口与原理、提出单一可分离改动，再进行定向测试、邻近回归、完整230回归。
- **安全硬约束**：不能用新增碰撞、车身越图增长、原成功场景损失来换取净到达数；几何地图外伸是审核信号，不自动定性为交通法规违规。
- **证据边界**：固定帧反事实不是闭环胜利；前缀安全不代表长期安全；无交通到达不证明有交通可到达；当前族内全冲突不证明物理不可行。
- **衡量进度**：到达/碰撞/超时、原成功保留、实际目标框进入、道路外伸、最早失去恢复见证、停车与等待时长、完成时间与动作稳定性。计算时延保留日志用于工程验收，现阶段优先解决正确性，不以单纯降低均值为主要研究目标。
- **达成目标**：230场100%是开发集阶段目标，不等于未知交通环境100%安全或泛化；对终帧新出现车辆要明确不可观测边界。

## 5. 给 Codex 的具体阅读与输出任务（只读）

**先阅读本文件、上述 r43 源码和现有失败归因，再分别查阅开源算法的 README、核心实现与论文来源**。对于每个建议，输出如下六项：

1. **原项目实际机制**：源码入口、关键状态/参数、算法假设和限制，附链接；区别代码事实与论文表述。
2. **r43 的真实缺口**：引用现存失败场景与具体失败窗口/诊断；不猜测未记录内部状态。
3. **迁移的最小思想**：能在统一执行框架内新增或改进哪个机制，为什么不需要替换整个架构。
4. **适用与不适用条件**：动力学、地图、W1信息范围、终帧出生、近远期安全证据差异。
5. **最小验证设计**：什么观察支持/推翻假设，哪些场景和指标必须保持，可能引入什么回归。
6. **研究优先级**：按预期对共性失败的解释力、可验证性、对 r43 的入侵程度排序；不得承诺成功场数。

**当前任务边界：只读研究与形成可评审提案；不自动更改生产代码、不运行新闭环、不自动遍历大量变体、不改 XML 或封存输入/结果、不访问 HOLD。** 需要进入具体实验时，单独提交方案，待用户明确授权。

**我们的原则**：不问“哪个开源算法可以整个搬来”，而问“r43 为什么在这一类状态失败，哪一种成熟算法思想可以最小代价改变这个机制，并且如何证明它没有破坏其他场景？”
