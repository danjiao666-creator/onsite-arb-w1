# 可行性判断的根本问题与证据边界

日期：2026-10-07。用户指出前述修复仍未打到根本。本记录纠正研究结论，不将局部收益视为核心模型已可靠。

## 当前判断

ARB+W1 的核心问题候选是可行性判断失真：仲裁器用理想路线占用、单一周车外推和几何近似，决定候选是否安全、能否到达。但这些占用并不等于实际控制执行和真实交通占用。假安全会释放危险动作，假无解会造成不必要制动与等待。两类错误共存，使降低保守成本和更积极选择反复产生新的事故。

此判断已有具体反例，但尚未量化其对全部失败的因果覆盖。不能宣称它已是唯一或覆盖多数失败的根因。

## 已确证反例

1. 自车占用不遵循执行动力学。`arbiter.py` 用 `path.pose(S, e0*exp(-t/1.5))` 推演横向位置，朝向取路线切向；v=0 时仍会横移。实际自行车模型停车时位置不变。`8_621_merge_622` 有同状态、同候选的理想占用无碰而控制推演重叠证据。见 `shared_contract_audit_r5.md`、`r5_collision_roots.json`。
2. 已见周车的未来不确定性没有进入可行性判断。W1 将当前估计加速度持续外推6秒、转率指数衰减，只返回一条占用。路口起步、加速和后车再加速反例在 `r5_collision_index.md` 中；仅换成CV仍会漏。未来真实轨迹只用于离线诊断。
3. 形状误报消耗真实可行解。`1010follow941` 的邻道16.67m长车被固定五圆侧向过膨胀。首帧8个候选经官方控制执行、对完整6秒真实交通均无重叠，却被预测冲突封锁；强刹后真实安全候选逐渐消失。见 `follow941_full_horizon.json`。
4. 可行性受装配与任务口径污染。连续换道的目标端点投影和走廊重复拼接产生8-12m急横移；到达后的风险仍参与当前排序。它们是确定缺陷，但修复闭环收益不等于预测和执行模型已可靠。

## 前述分类必须收紧

- 7场对象临近事故才出现是观测事实；其中2场首次出现即结束，排除了针对该对象的当帧反应。它不证明所有更早通用行为无解，也不证明出生是整场唯一主因。
- 全候选预测碰撞不等于物理无解。`1010` 完整6秒反事实已经推翻这一等同；其它检查若只覆盖到原日志终止，应标明截断窗口。
- 局部评分改变覆盖24场或20场，说明机制影响选择；标签重叠，不能相加，不能当作这些超时都已解释或可救。
- 31/32场无交通能按时到达，排除预算/目标本身必然失败；不证明真实交通下均存在可执行解。
- 26,954动作官方单步复演误差0，验证日志和台架执行；不能据此称规划的6秒占用推演正确。

## 下一项可证伪检验

停止扩大策略改动，固定r5的候选、成本和选择器，先测量内部可行性判定。

| 自车占用 | 周车占用 | 检验目的 |
|---|---|---|
| 原理想路线 | 原W1 | 原判定与动作复现 |
| 官方控制执行 | 原W1 | 隔离自车推演失配 |
| 原理想路线 | 真实未来 | 隔离周车外推误差 |
| 官方控制执行 | 真实未来 | 判断原候选集合是否确有可执行解 |

所有对照使用同一冻结状态、同一候选；按平台控制周期检查完整矩形，保持对象出生时间。不能用尚未出现对象的未来信息在线规划。成功场景也要作为对照，才能测量误报而不是只从失败反推原因。

核心输出应是按预测时距分组的假安全/假无解、首次真实可行解丢失时间，以及早期决策是否消耗可恢复空间。只找到失败末端的预测误差，不足以建立整场因果链。需要验证上述替换在早期状态是否改变可行解，并以闭环单因素修复验证终末结果。

`goal_box_r19_devreg130` 是此前已实现局部修复的完整回归；其结果由原始日志和双基准审计给出，不作为这项核心检验的替代。固定基准、HOLD和默认入口保持既有项目边界。
