# 理解这套系统的学习顺序

目标是看到一帧回放能解释为什么这样开，看到失败能沿数据流定位偏差。先贯通一个场景，再深入公式和代码。

## 三个基本概念

| 概念 | 问题 | 例子 |
|---|---|---|
| 路线/路径 | 沿哪里走 | 沿本车道前进，在指定位置移入左车道 |
| 轨迹 | 每个未来时刻在哪里 | 2s后仍在原车道，4s后进入目标车道 |
| 控制动作 | 当前帧怎样让车动 | 加速度-1m/s²，前轮角.03rad |

同一路径，速度不同就有不同轨迹；规划轨迹需要控制器实际实现。每帧重新观测，计划与执行形成反馈。

## 一个横穿场景

以下是假设数字，不是真实r99记录。周车在2.4–3.2s占据交叉区；自车加速候选在1.4–2.0s经过，匀速候选在2.7–3.4s经过，减速候选在4.5–5.2s经过。匀速时占用时间重叠，另两种时间错开。下载[教学示意](onsite-time-occupancy.html)后用浏览器打开切换候选。

时间错开只说明这个教学例子里的交叉区占用不重叠，不证明道路上所有对象、所有预测分支和实际执行都安全。

1. Observation给自车和周车当前状态。
2. W1利用周车历史估运动方向和加减速，提供未来占用。
3. Route决定自车空间路径；汇入时可比较不同换道起点。
4. Arbiter比较沿路径的速度候选，寻找占用时刻合适的方案。
5. CloseGuard在近车时推演真正控制和执行，修正短窗冲突。
6. 官方执行首动作，下一帧从实际状态重算。

## 分层阅读任务

| 顺序 | 阅读位置 | 需要能回答的问题 |
|---|---|---|
| 1 输入和闭环 | onsite_replay.py、bench/sim.py | 官方给什么，算法不知道什么，为什么只执行首步？ |
| 2 路径几何 | geometry.py、route.py | x/y如何变s/e，五次混合如何生成换道，曲率为何影响速度？ |
| 3 世界模型 | world.py | 位置历史如何变速度，加速度低通为何滞后，转向为何衰减？ |
| 4 主规划 | arbiter.py、native_profile.py | 27种候选如何推演，余隙与时间预算如何改变排序？ |
| 5 路线选择 | onsite_dynamic_route.py | 同一路线为何有多种换道时机，何时锁定？ |
| 6 执行与守卫 | control.py、native_execution.py、onsite_close_guard.py | 理想轨迹与实际轨迹哪里不同，守卫能救什么、不能保证什么？ |
| 7 证据与失败 | validation、release_review、PAUSED_STATUS | 失败来自输入、预测、候选、排序还是执行？ |

每次阅读做四件事：写明输入单位，列出中间量，用一个数值例子解释输出，再检查失败条件。不要从背全部参数开始。

## 诊断框架

- 路线错：即使无交通也无法朝目标行驶，检查图搜索、目标框和换道走廊。
- 预测错：相同动作按预测不碰，但真实周车在关键时刻出现在其他位置。
- 执行错配：主层假设的位置与真实控制推演偏离，检查积分、转角限制和横偏。
- 候选遗漏：有合适运动，但有限候选无法表示，不要把all_collide当物理无解。
- 排序不当：可行方案已经存在却未被选中，检查可行性优先、跟车、预算和一致性。
- 期限不够：区分无交通几何/速度预算不足和交通导致的延误。

后续调优必须保留原成功和无新增碰撞。学习与离线证据读取可以继续；实验恢复须遵循用户当前授权。
